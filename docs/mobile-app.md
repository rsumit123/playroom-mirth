# PlayRoom — Mobile App (Android via Capacitor)

## Overview

The PlayRoom mobile app is a **Capacitor wrapper** around the existing React web frontend. Capacitor embeds the web app inside a native Android WebView, allowing us to ship to the Google Play Store while maintaining a single frontend codebase.

### Key Principle

**The web app and mobile app share the same source code.** Capacitor does not modify the React source — it takes the Vite build output (`dist/`) and packages it into a native Android project.

```
frontend/
├── src/                    # Shared React source (web + mobile)
├── dist/                   # Build output consumed by both Vercel and Capacitor
├── android/                # Native Android project (generated by Capacitor)
│   ├── app/
│   │   ├── src/main/
│   │   │   ├── AndroidManifest.xml
│   │   │   ├── assets/public/    # dist/ gets copied here by `cap sync`
│   │   │   └── java/.../MainActivity.java
│   │   └── build.gradle
│   └── build.gradle
├── capacitor.config.ts     # Capacitor configuration
└── package.json            # Includes @capacitor/core + @capacitor/cli
```

## Architecture

### How Requests Flow

```
┌─────────────────────────────────────┐
│         Android Device              │
│  ┌───────────────────────────────┐  │
│  │   Capacitor Native Shell      │  │
│  │  ┌─────────────────────────┐  │  │
│  │  │   WebView (Chrome)      │  │  │
│  │  │  ┌───────────────────┐  │  │  │
│  │  │  │  React App (dist/) │  │  │  │
│  │  │  └─────────┬─────────┘  │  │  │
│  │  └────────────┼────────────┘  │  │
│  └───────────────┼───────────────┘  │
└──────────────────┼──────────────────┘
                   │ HTTPS + WSS
                   ▼
         charade-api.skdev.one
         (FastAPI + Socket.IO)
```

- The React app runs inside a native WebView (powered by the device's Chrome engine)
- All API calls and Socket.IO connections go to `charade-api.skdev.one` — same as the web app
- Capacitor provides a bridge for native APIs (push notifications, haptics, etc.)

### What Changes vs Web

| Aspect | Web | Mobile (Capacitor) |
|--------|-----|-------------------|
| Hosting | Vercel CDN | Bundled in APK |
| Updates | Instant (redeploy) | App store update OR live update plugin |
| API calls | Same (`charade-api.skdev.one`) | Same |
| Socket.IO | Same | Same |
| Auth | Google Sign-In (web popup) | Google Sign-In (native or web fallback) |
| Push notifications | Not supported | Firebase Cloud Messaging |
| Deep links | URL-based | App Links (intent filters) |

## Build & Deploy Pipeline

### Prerequisites

- **JDK 21**: `brew install openjdk@21`
- **Android SDK**: Installed at `~/Library/Android/sdk` (platform-tools, platforms;android-35, build-tools;35.0.0)
- **JAVA_HOME**: `export JAVA_HOME=/opt/homebrew/opt/openjdk@21/libexec/openjdk.jdk/Contents/Home`

### Build Debug APK (for testing)

Run all commands from `frontend/`:

```bash
# 1. Build frontend with production env vars
cd /Users/rsumit123/work/charade-chat/frontend
VITE_API_BASE=https://charade-api.skdev.one \
VITE_SOCKET_URL=https://charade-api.skdev.one \
VITE_GOOGLE_CLIENT_ID=929006071236-55m4f4gujp7nnu9ldirbkrmr4qn30ng1.apps.googleusercontent.com \
npm run build

# 2. Sync web assets to Android project
npx cap sync android

# 3. Build debug APK
export JAVA_HOME=/opt/homebrew/opt/openjdk@21/libexec/openjdk.jdk/Contents/Home
cd android && ./gradlew assembleDebug

# Output: android/app/build/outputs/apk/debug/app-debug.apk
```

### Build Release AAB (for Play Store)

```bash
# 1. Build frontend (same as debug)
cd /Users/rsumit123/work/charade-chat/frontend
VITE_API_BASE=https://charade-api.skdev.one \
VITE_SOCKET_URL=https://charade-api.skdev.one \
VITE_GOOGLE_CLIENT_ID=929006071236-55m4f4gujp7nnu9ldirbkrmr4qn30ng1.apps.googleusercontent.com \
npm run build

# 2. Sync
npx cap sync android

# 3. IMPORTANT: Bump versionCode in android/app/build.gradle
#    (must be higher than previous Play Store upload)
#    versionCode 3  →  versionCode 4
#    versionName "1.2.0"  →  "1.3.0"

# 4. Build signed release AAB (signing passwords come from the environment)
export PLAYROOM_KEYSTORE_PASSWORD=... PLAYROOM_KEY_PASSWORD=...
export JAVA_HOME=/opt/homebrew/opt/openjdk@21/libexec/openjdk.jdk/Contents/Home
cd android && ./gradlew bundleRelease

# Output: android/app/build/outputs/bundle/release/app-release.aab
```

### Deploy to Play Store

1. Upload `app-release.aab` in **Play Console > Testing > Closed testing > Releases > Create new release**
2. Add release notes (max 500 chars):
   ```
   <en-US>
   Your release notes here
   </en-US>
   ```
3. Review and roll out

### Signing Key

- **Keystore**: `frontend/android/keystore/playroom-release.jks` (gitignored, NEVER commit)
- **Password**: not stored in the repo. Export `PLAYROOM_KEYSTORE_PASSWORD` and `PLAYROOM_KEY_PASSWORD` before `./gradlew bundleRelease` (keep the values in a password manager)
- **Alias**: `playroom`
- **BACK THIS UP** — if lost, you can never update the app on Play Store

### Google Sign-In SHA-1 Fingerprints

Three Android OAuth clients exist in Google Cloud Console (project `polar-pillar-450607-b7`):

| Build type | SHA-1 | Purpose |
|-----------|-------|---------|
| Debug keystore | `C2:34:45:6D:0A:06:9F:74:66:BB:D0:7F:91:EA:90:49:92:51:58:33` | Local debug APKs |
| Release keystore | `74:1A:6F:F8:95:FC:A4:37:E8:11:53:63:00:86:34:0E:6C:F5:58:93` | Sideloaded release APKs |
| Play Store signing | (found in Play Console > Setup > App signing) | Play Store installs |

To get debug SHA-1:
```bash
/opt/homebrew/opt/openjdk@21/libexec/openjdk.jdk/Contents/Home/bin/keytool \
  -list -v -keystore ~/.android/debug.keystore -alias androiddebugkey -storepass android 2>&1 | grep SHA1
```

### Web (unchanged)
```bash
npm run build          # → dist/
# Deploy dist/ to Vercel (auto-deploys on git push to main)
```

### Commands Reference

| Command | What it does |
|---------|-------------|
| `npx cap sync android` | Copies `dist/` to Android project + syncs native plugins |
| `npx cap open android` | Opens the Android project in Android Studio |
| `npx cap run android` | Builds and runs on a connected device/emulator |
| `npx cap copy android` | Copies only web assets (faster than sync, skips native plugin sync) |

## Configuration

### capacitor.config.ts

```typescript
import { CapacitorConfig } from '@capacitor/cli';

const config: CapacitorConfig = {
  appId: 'com.skdev.playroom',        // Unique app ID for Play Store
  appName: 'PlayRoom',
  webDir: 'dist',                      // Vite build output
  server: {
    // In production: app loads from bundled assets (no URL needed)
    // For dev: uncomment to load from Vite dev server
    // url: 'http://LOCAL_IP:5173',
    // cleartext: true,
  },
};
```

### Environment Handling

The app connects to the same backend as the web version. API URLs are baked in at build time via Vite env vars:

```bash
# Production build (same for web and mobile)
VITE_API_BASE=https://charade-api.skdev.one \
VITE_SOCKET_URL=https://charade-api.skdev.one \
VITE_GOOGLE_CLIENT_ID=929006071236-55m4f4gujp7nnu9ldirbkrmr4qn30ng1.apps.googleusercontent.com \
npm run build
```

To detect if running inside Capacitor (for platform-specific behavior):
```typescript
import { Capacitor } from '@capacitor/core';

if (Capacitor.isNativePlatform()) {
  // Running in Android app
} else {
  // Running in browser
}
```

## Platform-Specific Considerations

### Google Sign-In
- Web: Uses Google Sign-In popup (existing flow)
- Android: Can use the same web-based OAuth flow inside WebView, OR use `@codetrix-studio/capacitor-google-auth` for native Google Sign-In
- The same `GOOGLE_CLIENT_ID` works for both, but you need to add the Android app's SHA-1 fingerprint to the Google Cloud Console

### Back Button
- Android's hardware/gesture back button needs handling
- Capacitor's `@capacitor/app` plugin provides `backButton` event listener
- Should navigate back in the app, not exit immediately

### Status Bar & Safe Areas
- Use `@capacitor/status-bar` plugin to control status bar appearance
- CSS `env(safe-area-inset-*)` for notch/punch-hole displays

### Push Notifications (Future)
- Use `@capacitor/push-notifications` + Firebase Cloud Messaging
- Useful for notifying players when it's their turn or when someone joins their room

### Deep Links (Future)
- Allow share URLs (`playroom.skdev.one/room/ABCD`) to open directly in the app
- Requires Android App Links configuration in `AndroidManifest.xml`

## Play Store Requirements

Before publishing to Google Play:

1. **App signing key** — Generate a keystore for signing the release APK/AAB
2. **Privacy policy** — Required URL (can host on `playroom.skdev.one/privacy`)
3. **App listing assets** — Screenshots, feature graphic, icon, description
4. **Content rating** — Complete the content rating questionnaire
5. **Target API level** — Must target the latest required Android API level
6. **AAB format** — Play Store requires Android App Bundle (.aab), not raw APK

## Development Workflow

### Day-to-day development
1. Work on `frontend/src/` as usual (hot reload with `npm run dev`)
2. Test in browser — the web app IS the mobile app
3. When ready to test on Android:
   ```bash
   npm run build
   npx cap sync android
   npx cap run android
   ```

### When to test on a real device
- Google Sign-In flow
- Socket.IO reconnection on mobile network switches
- Back button behavior
- Performance on lower-end devices
- Push notifications (when implemented)

## Risks & Mitigations

| Risk | Mitigation |
|------|-----------|
| WebView performance on low-end devices | Profile on a budget Android device early; optimize heavy renders |
| Google Sign-In in WebView may be restricted | Use native Google Sign-In plugin as fallback |
| App updates require Play Store review | Consider Capacitor live update plugin for web asset updates |
| Socket.IO disconnect on app background | Handle reconnection in `appStateChange` listener |
| Play Store rejection for "thin wrapper" | Add at least one native feature (push notifications) to differentiate |
